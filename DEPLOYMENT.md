# Deployment strategy

Decision: Vercel is the intended commercial hosting platform. Development remains at zero incremental cost using GitHub Actions and local testing. Do not deploy the commercial project to Hobby without confirming eligibility under current Vercel terms. Do not upgrade, deploy to production, attach a domain or activate payments without owner approval.

## Development

The current free prototype is client-side and exports static HTML via Next.js. Run `npm install`, `npm run typecheck`, `npm test`, `npm run build` and verify `out/index.html`. Static export is a development convenience, not a permanent architecture constraint. Remove it when introducing server routes and verify the resulting build before release.

## Vercel release gate

Confirm eligible plan, spending controls, Git integration, reviewed commit, environment separation and preview access. Use Next.js framework detection. Configure secrets only through protected environment settings. No real customer data in preview. No commercial production release without explicit approval.

## Acceptance

Verify EN/ES, adult consent, known and unknown birth time, invalid time zone, clearing inputs, score display, and both PNG card sizes on desktop and mobile. Check premium purchases remain disabled until release approval and that free birth data is not transmitted. Record actual preview URL and commit when verified. Robots metadata is not access control.

Cloudflare Pages is an optional static-hosting fallback, not the selected provider. No Cloudflare resources were created.

## Cloudflare Pages demo — required settings (P0 geography fix)

The country/city selector needs the GeoNames catalog in `out/geography/`. It is generated by
`npm run build` itself (Python 3 + network access to download.geonames.org), followed by a gate
(`scripts/verify-geography-artifact.mjs`) that **fails the deployment** if the catalog is missing,
partial without an explicit `GEOGRAPHY_COUNTRIES`, or the offline test fixture.

Settings to confirm in Cloudflare Pages → astralis-ai → Settings → Build (owner action, not visible to agents):

| Setting | Value |
|---|---|
| Framework preset | None (static export) |
| Build command | `npm run build` (or `npm run build:world`, now an alias) — **not** `next build` / `npm run build:app` |
| Build output directory | `out` |
| Environment variables | Must **not** set `GEOGRAPHY_COUNTRIES`. Optional: `NODE_VERSION=22`, `PYTHON_VERSION=3.11` |

`npm run build:app` (plain `next build`) and `npm run build:fixture` are for local development only.
If a deployment shows "El catálogo de lugares no está disponible", the catalog was not published:
check the Cloudflare build log for the "Geography gate" line.

### Fix: geography on its own release cycle
- `scripts/build-geography.py` installs the catalog pinned in `geography.lock.json` (URL + SHA-256) via `scripts/fetch-geography-release.py` and skips the import. One ~289 MB download from GitHub replaces ~250 GeoNames downloads and the processing. A hash mismatch is a hard failure, never a silent fallback. Without a lock file the old behaviour is unchanged (rebuild).
- `.github/workflows/geography-release.yml` builds the world catalog once, validates it (incl. rural Peru) and publishes `geography.tar.gz` + `geography.lock.json` as a GitHub prerelease. It uses `GITHUB_TOKEN` only: no new credentials, no cost.
- Narrative or UI commits no longer touch GeoNames. The catalog changes only when someone cuts a new `geo-*` release and commits the new lock.
- Tests: `tests/geography-release.test.mjs` (install, hash refusal, no lock → rebuild, unsafe tar member refused). Local end-to-end: lock → build → byte-identical catalog.

## Block 4 update: versioned catalog in a private repository (P0-B)
The catalog is distributed as an asset of a **release of this same repository**. Once the repo is private, the asset is private too, and nothing is made public.
- **Bundle:** `geography.tar.gz` = `geography/` (JSON shards + `ATTRIBUTION.md`) + `geography-stats.json`.
- **`ATTRIBUTION.md`:** GeoNames source URLs, CC BY 4.0 and its attribution line, version, generation time, build commit, and the transformations applied. It is also served at `/geography/ATTRIBUTION.md`. The site footer and the location picker already credit GeoNames.
- **`geography.lock.json`:** `version`, `url`, `assetApiUrl`, `sha256`, `bytes`, `generatedAt`, `builtFromCommit`, `previousVersion`, `source`, `countries`, `places`.
- **Release workflow checks:** catalog tests (incl. rural Peru); a bundle allowlist (only `geography/`, `.json`, `ATTRIBUTION.md`, `SOURCE.txt`); a private-pattern scan when the `PRIVATE_PATTERNS` secret exists; and a reinstall from the packed bundle, which must be byte-identical.
- **Authenticated download** (`scripts/fetch-geography-release.py`): with `GEOGRAPHY_TOKEN` set, it calls the GitHub API asset URL and then follows the redirect to signed storage **without** the token. The token is never printed (tested: `tests/geography-release.test.mjs`). A SHA-256 mismatch or a failed download is a hard error.
- **Update policy:** monthly, or when a geography bug needs new data. A person publishes a release `geo-YYYY.MM.DD`, then Claude commits the new lock file with `previousVersion` set.
- **Rollback:** revert the commit that changed `geography.lock.json` (old releases are kept as prereleases), or set the lock back to `previousVersion`.

## Block 4: CI cost controls for a private repository (P0-C)
Measured while the repo was public (so $0): the `preview` job averaged **69 min per run (max 122)** waiting for Cloudflare. That was ~85% of all job time. Foundation CI used 3 jobs × rounding-up.
Changes (critical checks are unchanged):
- **Foundation CI:** a single job instead of three, since GitHub rounds each job up to the minute. Superseded runs are cancelled. npm and Playwright are cached. CI is skipped when a PR (or a push to the integration branch) changes only docs. GitHub evaluates path filters on the whole PR diff, so a docs commit inside a PR that also changes code still runs CI. The site artefact is uploaded only on failure (it was 13.5 MB per run, 1.1 GB in total). Evidence is kept 5 days.
- **Preview verify:** only on PRs labelled `verify-preview`. At most 40 min of polling at 60 s. Superseded runs are cancelled.
- **Runner smoke:** manual only.
- **World import:** concurrency cancel, npm cache, shorter retention.
- **Agents:** push in batches. Run tests locally before pushing.

**Estimate after the changes:** ~10 pushes/day × ~4 min ≈ 1,200 min/month. Gate verifications ≈ 10 × 25 min = 250. World imports and the catalog release ≈ 60. **Total ≈ 1,500 of 2,000 free minutes.** Artefacts: the 1.27 GB stored today expires within 7 days (14 days for some). New uploads ≈ 10 MB per run × 5 days, well under 500 MB. The `astralis-web-preview` artefacts (1.1 GB) are not sensitive; deleting them early would free storage immediately, but that needs the founder's yes. Billing stays off: GitHub Free blocks extra usage instead of charging, unless a payment method and spending limit are set.
